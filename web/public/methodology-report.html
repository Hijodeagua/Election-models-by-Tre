Two questions, answered straight

Yes
Does it update with new polls automatically? A scheduled GitHub Action runs twice a day (10:00 & 22:00 UTC): it pulls fresh polls from VoteHub, Wikipedia’s Senate pages, RealClearPolling and the prediction markets, re-runs every model — including the new state-space fits and the 50,000-run Senate simulation — and commits the results, which redeploys the site. A second job recalibrates the error model monthly; a third can retrain parameters quarterly behind the holdout gate. One catch: scheduled jobs run from the main branch, and this session’s work lives on the audit branch — the upgraded pipeline goes fully automatic the moment the branch merges. This report page itself is a session snapshot, not a live dashboard.
No
Is the NYT “vibes” analysis in these numbers? The plumbing exists — a media-sentiment overlay that nudges each race’s margin, simulated side-by-side with the base forecast — but it currently runs on neutral placeholder data because the NYT pipeline has never been given an API key. Today “with vibes” equals the base forecast exactly. Per the audit it stays out of the headline numbers until it’s fed real data and validated against actual outcomes. It’s a switch waiting for evidence, not a missing feature.

Wave 1 — five correctness bugs, found and fixed

Each verified in the code before touching anything. All fixes are covered by new regression tests.

Fixed
The training scorekeeper compared incompatible numbers. Predictions kept undecided voters in; election results didn't. Every prediction looked ~4 points too low, and a candidate leading 48–44 was scored as a predicted loser. Both sides now normalized to the two-party share before scoring.
Fixed
Two different pollster grade books. The live site graded pollsters on one scale, model training on an older hand-typed table with entirely different values (Marist: 2.9 vs 1.77). One source of truth now; unknown pollsters get the documented skeptical default (1.41, not 1.5).
Fixed
Made-up opposition numbers. The advanced model estimated “Approve,” then declared Disapprove = 100 − Approve — but 5–15% of respondents pick neither, so disapproval was inflated and its error bar was fiction. Both sides now estimated independently, with real credible intervals.
Fixed
Tracking polls counted many times. Daily trackers and duplicate likely-voter/all-adult releases each entered with full weight, letting single firms dominate. A dedup rule (one poll per pollster per overlapping window) trimmed the approval feed from 2,906 rows to 1,825 real polls.
Fixed
Congress polls in the presidential average. The bug behind the headline tile: Congress approval (~15% approve) was quietly dragging the president’s number down by nearly two points. Found while verifying the dedup fix — not in the original briefing.

Wave 2 — four structural upgrades

Shipped
The good model now publishes. The Jackman state-space model — which removes each pollster’s systematic lean instead of merely down-weighting it — was written months ago but never ran in production (“too heavy for CI”). Measured: ~6.5 minutes, converged. It now runs in the twice-daily refresh and publishes house-effect-corrected estimates with full uncertainty bands. Corrected approval: 40.3 [38.6–42.0].
Shipped
Honest training protocol. Parameter training now uses rolling-origin cross-validation: tune on older cycles, score once on the most recent cycle, and keep the result only if it beats the hand-set defaults there. A quarterly CI job runs it; a failed gate changes nothing. No trained parameters ship without out-of-cycle evidence.
Shipped
Every hand-set dial stress-tested. Seven judgment-call settings were swept through the live forecast. One dominates all others — see the chart below.
Shipped
Fat-tailed error + a fitted seat curve. Polling catastrophes (2016-style correlated misses) now have a place in the simulation, chosen because they score better on 98 historical races — and the generic-ballot→seats conversion is fitted from 26 years of results with a published uncertainty band.

Fat tails win the backtest

What’s next

In priority order. The first two are pushes of a button; the rest are real work.

  • Merge the branch. Everything above goes fully automatic — twice-daily refresh with the corrected feeds and state-space estimates, monthly recalibration with the tail comparison.
  • Trigger the first training run. The train_parameters workflow (poll archive is reachable only from CI) produces the first parameter set with out-of-cycle evidence — or fails the gate and changes nothing.
  • Ground senate_responsiveness empirically. The sensitivity sweep’s loudest result: this one judgment call moves the headline by 33 points. Fit it from historical Senate results vs national swing instead of assuming 1.0.
  • Feed and validate the vibes signal. Add the NYT API key, accumulate a real sentiment series, then backtest it against race outcomes before it touches a published number.
  • Regional error covariance. One national factor still understates clustered misses (the 2016 Midwest pattern). Deferred deliberately — with ~13 competitive races a cycle the fit would be noise — revisit once 2026 results join the archive.
  • Generic-ballot bias correction for the seat curve (needs archived per-cycle ballot averages), plus the Phase 5 scoring metrics (CRPS, PIT, coverage) in the calibration job.
